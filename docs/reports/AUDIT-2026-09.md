# Prism repository audit — September 2026

Read-only audit of `0.1.0-alpha.5`. No production code or tests changed. Findings are ordered by severity and practical impact. No Critical issue was established; a large architectural rewrite is not warranted.

## Scope and execution map

- **Download:** preload → validated download IPC → `DownloadManager` → metadata/yt-dlp → optional generic download, subtitle embedding, split audio/video, or explicit ProRes conversion → output delivery → history/progress. The manager owns download concurrency, pause/resume, the two-hour timeout, and startup reconciliation.
- **Local media:** conversion/remux and transcription create history records independently of the download manager. FFmpeg/Whisper workers generally register with `processRegistry`; probing, waveform, preview, and runtime-extraction workers do not consistently do so.
- **State:** electron-store holds settings/history. Main publishes revisioned progress and whole-history snapshots; Zustand merges them. Progress IPC and persistence already have useful throttling.
- **Files/security:** main owns native dialogs, file operations, shell launches, and the `local:`/`prism-media:` protocols. Preload exposes individual APIs rather than raw IPC invocation. IPC shape validation does not consistently establish authority over supplied paths.
- **Runtime/release:** packaged binaries live under `resources/bin/win`; models and optional CUDA runtime install into userData. yt-dlp updates validate a downloaded binary before changing its runtime pointer. Electron updates use GitHub and allow prereleases. Packaging, native-resource verification, release gates, and relevant tests were inspected.

Static UI/CSS was not exhaustively reviewed. No speculative dependency migration, new framework, or broad cleanup is recommended. Investigation stopped after the critical boundaries were covered and remaining candidates became lower-value or runtime-dependent.

## Confirmed issues

### A01 — History reconciliation can delete new jobs or restore stale job state

- **Severity:** High. **Category:** race / persistence. **Confidence:** High.
- **Files:** `src/main/ipc/history.ts:15-18,33-35,66-89,93-100`; concurrent writers in `src/main/download/queue.ts:189-192` and `src/main/download/job-state.ts:56-85`.
- **Problem/scenario:** `scanHistory()` snapshots the whole array, awaits filesystem checks, then replaces the whole stored array. A download added while a stat is pending is absent from the snapshot and gets deleted. Concurrent completion, remove, clear, or locate changes can likewise be reverted. Sharing one reconciliation promise prevents two scans, not other writers.
- **Why it matters:** Lost jobs/history and incorrect crash-recovery state. The lost-new-record scenario was reproduced.
- **Minimal fix:** Accumulate file-state observations by ID, then re-read current history and merge only those fields into still-matching records. Do not resurrect removed IDs; discard an observation if the record's paths/status changed during the scan.
- **Regression test:** Gate a stat, add a job and update/remove an existing record, release the stat, and assert all concurrent mutations survive.

### A02 — Generic download filesystem errors can escape the promise and terminate the process

- **Severity:** High. **Category:** error handling / filesystem cleanup. **Confidence:** High.
- **Files:** `src/main/download/generic-download.ts:159-180,213-251`; `test/generic-download.test.ts:139-150`.
- **Problem/scenario:** `saveResponse()` opens a WriteStream without a continuously installed error handler while awaiting response chunks. An asynchronous open/write error outside its temporary `once(..., 'drain'/'finish')` listeners is an unhandled EventEmitter error. Separately, cancellation calls `destroy()` and removes the path without awaiting stream closure; the asynchronous open can create the file after removal.
- **Why it matters:** A routine filesystem failure can escape normal job failure handling and bring down the main process. The EEXIST crash was reproduced; the existing cancellation test also failed on Windows.
- **Minimal fix:** Use Node's promise-based `pipeline` with the existing async chunk/progress handling, or otherwise own stream errors and completion for the entire stream lifetime. Check cancellation before opening, await closure before cleanup, and only remove an output this invocation actually created. Preserve the original failure.
- **Regression test:** Keep the existing cancellation test; add an asynchronous open/write-error case that rejects without an uncaught error and preserves a pre-existing destination.

### A03 — “Unique” output paths are not reserved across concurrent jobs

- **Severity:** High. **Category:** concurrency / data loss. **Confidence:** High.
- **Files:** `src/main/download/utils.ts:223-240`; `src/main/download/ytdlp.ts:1562-1585`; `src/main/download/temp-dirs.ts:93-102`; `src/main/download/conversion.ts:66-76`; `src/main/download/converter.ts:438-472`; `src/main/transcription/runner.ts:49-57,137,261-262`.
- **Problem/scenario:** `ensureUniquePath()` checks existence but reserves nothing. Two same-title downloads can choose one path before their asynchronous moves. Two conversions can choose one path before hardware detection/FFmpeg opens it; transcription chooses its final name before potentially lengthy preparation. FFmpeg uses `-y`; rename/copy delivery also permits replacement.
- **Why it matters:** Jobs can silently replace each other's outputs and report the same final path. The two-delivery overwrite was reproduced with real filesystem operations.
- **Minimal fix:** Reserve destination ownership before any await, using canonical Windows path keys shared by all output-producing jobs, and release it in `finally`. Pair reservation with safe final commit/no-clobber behavior for files created externally. Do not treat an existence-check loop as a reservation.
- **Regression test:** Hold two same-name jobs before output creation; release both and assert distinct complete files containing each job's own bytes. Include conversion/transcription callers, not just sequential unique-name tests.

### A04 — App shutdown only cancels download-manager jobs, not all native work

- **Severity:** High. **Category:** child processes / shutdown reliability. **Confidence:** High.
- **Files:** `src/main/index.ts:232-236`; `src/main/download/queue.ts:30,245-246,425-428`; `src/main/download/conversion.ts:133-171`; `src/main/transcription/runner.ts:204-243,276-312`; `src/main/download/media-probe.ts:38-54,218-269`; `src/main/download/waveform.ts:11-37,54-101`; `src/main/media-preview.ts:31-65`; `src/main/transcription/gpu-runtime.ts:132-156`.
- **Problem/scenario:** `before-quit` calls `shutdown()`, which only iterates `ACTIVE_DOWNLOADS`. Conversion/remux/transcription are not added to that map even when their children are registered. Probe, waveform, audio-preview, and archive-extraction children bypass that registry altogether. Close Prism during one of these operations and no shutdown cancellation is issued for that worker.
- **Why it matters:** Windows does not automatically terminate all child processes when their parent exits. Workers can continue using CPU/disk or modifying outputs after the UI is gone. Preview/waveform/probe operations also lack an overall deadline and cancellable ownership.
- **Minimal fix:** Give the existing process registry a shutdown path covering every owned child, register auxiliary workers too, and abort active transfer/install controllers. Stop new work and perform bounded termination/closure before exiting. Add deadlines to auxiliary work that has no queue timeout.
- **Regression test:** Start one worker of each ownership class, trigger actual app quit, and assert their process trees exit and no output keeps growing. Include an auxiliary worker with no download ID.

### A05 — File-opening IPC grants arbitrary executable launch authority to renderer code

- **Severity:** High. **Category:** Electron security / IPC authority. **Confidence:** High for the exposed capability; no renderer exploit was found.
- **Files:** `src/preload/index.ts:36-39`; `src/main/ipc/history.ts:207-230`; `src/main/ipc/download.ts:109-123`; `src/shared/ipc-schemas.ts:230-267,283-290`.
- **Problem/scenario:** `history:openFile` accepts any nonempty renderer-supplied path, resolves it, checks access, and passes it to `shell.openPath`. It does not require a history record, a main-approved selection, a media type, or confirmation. Renderer code that gains execution can therefore request an existing `.exe` or shell-associated script, rather than being limited to Prism media. Related probe/preview/output-directory APIs also accept paths without a main-owned authorization record.
- **Why it matters:** This is a material privilege expansion across an otherwise sandboxed Electron boundary. It is **not** evidence of remote code execution from an ordinary media URL or of an existing XSS. Local import and user-selected external folders are legitimate and must remain supported.
- **Minimal fix:** Resolve history-open actions by history ID in main; reject executable/script shell targets. For imported files/directories, retain explicit main-approved selections or opaque grants. Validate IPC sender/frame as well. Do not simply restrict every media API to Downloads or rely on filename sanitization as authorization.
- **Regression test:** From the bridge, attempt to open an unrelated executable or unapproved path and assert `shell.openPath` is not called; approved media/history actions must still work.

### A06 — Batch remux reuses one selected file's output name and track selection

- **Severity:** High. **Category:** media correctness / data loss. **Confidence:** High.
- **Files:** `src/renderer/pages/media-tools-page.tsx:447-482,523-581,584-596`; `src/main/download/remux.ts:163-179`; `src/main/download/remux-job.ts:194-202`.
- **Problem/scenario:** The selected item populates global output name/directory and stream indices; `startOne(item)` sends those values for every batch member. Add compatible `a.mp4` and `b.mp4`, select `a`, choose MKV, and run the batch: both target `a.mkv`. With overwrite enabled, the later item replaces the earlier result. With keep-original disabled too, both sources can be deleted after their individually successful remuxes, leaving only the last result. Selected-file stream indices and trim values are also reused on different media.
- **Why it matters:** Without overwrite, results are misleadingly named; with the destructive options, this can lose batch outputs and originals. Global codec/container settings can be intentional; source-derived names and stream indices are not safely interchangeable.
- **Minimal fix:** Derive unedited output names from each item at request construction. Restrict per-file track/trim controls to the selected item or store those values per item. Reject colliding explicit output names in overwrite batches before starting.
- **Regression test:** Build/run a two-file batch with different stream layouts and overwrite enabled; assert distinct intended destinations, correct per-file mappings, and no earlier result/source loss.

### A07 — Pause intent is not enforced at subprocess and finalization boundaries

- **Severity:** Medium. **Category:** queue lifecycle. **Confidence:** High.
- **Files:** `src/main/download/process-registry.ts:26-35,68-80`; `src/main/download/converter.ts:397-427`; `src/main/download/ytdlp.ts:1467-1474,1693-1704,1898-1909,1945-1956`.
- **Problem/scenario:** Registering a child checks cancelled intent but not paused intent. Pause between split video's exit and audio's spawn permits the audio stage to run. FFmpeg maps cancellation but not pause; subtitle embedding catches its pause-induced error as an ordinary nonfatal embed failure and can continue to delivery/completion. Completion checks cancellation only.
- **Why it matters:** Pause can consume more bandwidth/CPU, modify final output, or complete instead of pausing. Temp preservation alone does not fix the state transition.
- **Minimal fix:** Make registration and subprocess error translation respect pause. Rethrow pause/cancel from best-effort subtitle catches. Check intent before subsequent stages and irreversible delivery/completion; retain the existing paused temp-directory behavior.
- **Regression test:** Pause between video/audio stages and during subtitle FFmpeg; assert no subsequent stage/final delivery occurs, status becomes paused, and resume uses preserved work.

### A08 — Concurrent model downloads share a partial file and overwrite cancellation ownership

- **Severity:** Medium. **Category:** model download concurrency. **Confidence:** High.
- **Files:** `src/main/transcription/models.ts:327-372,428-434`; `src/main/ipc/transcription.ts:58-60`.
- **Problem/scenario:** `downloadModel()` has no same-model in-flight guard. Two calls can both pass asynchronous verification, write the same `.part`, and replace `activeDownloads[model.id]` with the second controller. Either completion deletes that map entry while the other may still run.
- **Why it matters:** Corrupted partial downloads, wasted bandwidth, conflicting progress, and incomplete cancellation. Final checksum verification is a safeguard against accepting corrupt model bytes, not against this concurrency failure.
- **Minimal fix:** Claim the model ID synchronously before the first await and share/reject duplicate work. Only its owner may clear the in-flight entry; coordinate delete with that same owner.
- **Regression test:** Two simultaneous requests for one model must start one writer/transfer; cancellation and deletion must wait for that transfer's closure.

### A09 — Timeout failure is overwritten as user cancellation

- **Severity:** Medium. **Category:** timeout / terminal state. **Confidence:** High.
- **Files:** `src/main/download/queue.ts:102-131,263-310`; `src/main/download/process-registry.ts:57-65`.
- **Problem/scenario:** Timeout records failed/`DOWNLOAD_TIMEOUT` after setting registry cancellation. The killed worker rejects; the manager catch classifies the registry flag as user cancellation and writes cancelled/`JOB_CANCELLED`. Direct history writes make this real even where progress merging offers terminal-state protection.
- **Why it matters:** The UI and persisted diagnostics lose the actual failure reason and retryable timeout state.
- **Minimal fix:** Preserve the first terminal cause for an attempt and distinguish timeout termination from user cancellation. Do not clear cancellation early merely to change classification; late subprocesses still need to be stopped.
- **Regression test:** Fire timeout, then deliver the worker's cancellation rejection; assert final history and progress remain failed/`DOWNLOAD_TIMEOUT`.

### A10 — Failed local conversions/transcriptions can leave untracked partial final outputs

- **Severity:** Medium. **Category:** filesystem / interrupted operations. **Confidence:** High.
- **Files:** `src/main/download/conversion.ts:133-171,206-258`; `src/main/transcription/runner.ts:181-185,261-262,313-317,378-387`; `src/main/download/temp-dirs.ts:69-79`.
- **Problem/scenario:** Conversion writes directly to the final output and its catch never removes that file. Whisper also writes directly to its final basename, but `actualOutput` is assigned only after `runWhisper` succeeds, so a partial output left by a failing/killed Whisper is not cleaned. Crashed `prism-whisper-*` WAV directories are outside the download startup-cleanup root.
- **Why it matters:** Failed/cancelled jobs consume disk and leave plausible-looking media/transcripts outside tracked completed history. Crash leftovers can be large.
- **Minimal fix:** Write job-owned work to staging paths, commit only after success, and clean owned partial outputs on failure after the child closes. Record intended owned paths before spawning. Add narrowly scoped startup cleanup for abandoned Whisper temp directories; never delete arbitrary source/user files.
- **Regression test:** Have FFmpeg/Whisper write a partial file then fail/cancel; assert no partial final result survives. Create an abandoned owned Whisper temp directory and assert recovery removes it without touching unrelated files.

### A11 — Audio preview cache has no eviction; tokens expire only when looked up again

- **Severity:** Medium. **Category:** disk / memory / privacy lifecycle. **Confidence:** High.
- **Files:** `src/main/media-preview.ts:13-24,69-98`; `src/main/index.ts:202-210`; `src/main/thumbnails.ts:65-107`.
- **Problem/scenario:** Preview generation keeps a full 128-kbit/s MP3 under `prism-audio-previews`. Files are never evicted. Every request creates another token; expiry deletes it only if that expired token is requested again. Closing the preview or application does not clean cached files. The separate thumbnail pruning implementation likewise has no caller in `src`.
- **Why it matters:** Repeated media use accumulates disk data, including private audio, after source/history removal. An hour-long preview is approximately 57.6 MB at the configured bitrate. Unused token entries accumulate during the session.
- **Minimal fix:** Add a bounded size/age eviction policy for generated caches and sweep expired tokens. Reuse/wire the existing thumbnail maintenance instead of creating another cache framework. Coordinate eviction with currently served/generated files. Worker cancellation is covered by A04.
- **Regression test:** With a fake clock and small size cap, expire unused tokens and cache files, preserve active preview files, and verify stale crash `.tmp` files are eventually removed.

### A12 — Media Tools initializes stream defaults before the probe arrives

- **Severity:** Medium. **Category:** renderer async state / media correctness. **Confidence:** High.
- **Files:** `src/renderer/pages/media-tools-page.tsx:349-380,447-482`.
- **Problem/scenario:** A new selected item has no probe. Its effect sees zero video streams, selects MP3, and empties track selections. The effect depends only on `selected.id`; later probe arrival for that same item does not rerun it.
- **Why it matters:** Adding a video can default Convert to audio-only MP3 and leave advanced track controls inconsistent with the actual file.
- **Minimal fix:** Initialize probe-dependent defaults only when the probe is available, and depend on its arrival separately from filename/directory selection. Avoid overwriting later intentional user edits.
- **Regression test:** Select an inspecting video, resolve its probe, and assert video-appropriate defaults and track selections appear without changing selection.

### A13 — Model/runtime cancellation stops transfer but not later activation stages

- **Severity:** Medium. **Category:** cancellation / runtime installation. **Confidence:** High.
- **Files:** `src/main/transcription/models.ts:388-406,433-434`; `src/main/transcription/gpu-runtime.ts:132-156,236-278` and `cancelGpuRuntimeInstall()`.
- **Problem/scenario:** Abort is observed by network work, but no check prevents model rename/marker activation after hashing, or CUDA extraction/copy/smoke-test/marker activation. Cancel during checksum verification or archive extraction can still install the component. CUDA's manual `response.pipe(stream)` error path also does not own destruction/closure of both streams before cleanup.
- **Why it matters:** A cancelled large operation can continue substantial disk/CPU work and finish installed. Incomplete stream closure complicates Windows cleanup.
- **Minimal fix:** Check abort between each long phase and immediately before activation; make archive extraction abortable through the process owner. Use `pipeline` for transfer teardown. Preserve resumable model parts intentionally, but never activate after cancellation.
- **Regression test:** Gate hashing and extraction, cancel, then release them; assert no installed marker/activation and no live child or write stream.

### A14 — Late transcription cancellation can be overwritten by completed

- **Severity:** Medium. **Category:** transcription terminal-state race. **Confidence:** High.
- **Files:** `src/main/transcription/runner.ts:313-346`; `src/main/download/queue.ts:374-395`.
- **Problem/scenario:** After Whisper succeeds, transcription awaits `readFile` before unconditionally publishing and directly persisting completed. Cancel during that await records cancelled; the continuation then replaces it with completed.
- **Why it matters:** The UI reports the opposite of the accepted action, and history/progress can disagree. This is a real await boundary, unlike a hypothetical race inside synchronous finalization.
- **Minimal fix:** Recheck cancellation after the transcript read and immediately before the synchronous completion commit; route it through the existing cancelled cleanup path.
- **Regression test:** Gate transcript reading after Whisper exit, cancel, release the read, and assert no completed event or completed history is written.

### A15 — Cross-drive delivery exposes partially copied final files and unsafe replacement

- **Severity:** Medium. **Category:** atomic writes / data preservation. **Confidence:** High.
- **Files:** `src/main/download/temp-dirs.ts:93-102`; `src/main/download/ytdlp.ts:1573-1585`.
- **Problem/scenario:** EXDEV, EPERM, or EEXIST falls back to `copyFile` directly into the final destination, then unlinks the source. Explicit overwrite also deletes the old destination before delivery. A crash mid-copy can leave a partial final file; overwrite plus a later disk/permission failure can lose the previous complete file. Final destination leftovers are not in the startup temp cleanup scope.
- **Why it matters:** Windows users commonly keep Downloads on a different drive from OS temp. A rename-or-copy helper is not an atomic commit across volumes.
- **Minimal fix:** Copy to a uniquely owned sibling temporary file on the destination volume, close/verify it, then commit. Retain the previous output until replacement is ready. Distinguish a genuine cross-volume move from access errors rather than blindly treating EPERM as a reason to overwrite by copy.
- **Regression test:** Interrupt/fail destination copying and replacement; assert the previous final file remains intact, no partial file appears under the final name, and owned staging files can be recovered/removed.

### A16 — Retry is offered for local jobs but dispatches only download requests

- **Severity:** Medium. **Category:** renderer action correctness. **Confidence:** High.
- **Files:** `src/renderer/components/row-card.tsx:108-130,248-257`; `src/main/download/conversion.ts:79-116`; `src/main/transcription/runner.ts:138-156`.
- **Problem/scenario:** Every failed/interrupted row gets Retry. The action always parses/requeues a DownloadRequest. Local conversion/transcription records have no such request and use `file://` URLs or formats the download schema rejects; failure is only logged to the console. A conversion originating from online history can instead re-download rather than repeat the requested conversion.
- **Why it matters:** A visible recovery action silently does nothing or performs the wrong operation.
- **Minimal fix:** Only offer this retry implementation for download jobs with reconstructible download requests. Do not pretend other jobs are retryable until their original operation can actually be reconstructed; show an actionable error if dispatch fails.
- **Regression test:** Failed local jobs must not invoke `addToQueue`; a failed download's Retry must preserve its original request.

### A17 — The documented empty speed limit cannot be saved

- **Severity:** Medium. **Category:** validation / settings correctness. **Confidence:** High.
- **Files:** `src/shared/ipc-schemas.ts:108-110,292`; `src/main/store.ts:17`; `src/renderer/pages/settings-page.tsx:108-113,165-179`.
- **Problem/scenario:** The UI says “Empty for none” and the default is empty, but `downloadSpeedLimit` uses `requiredString`. Clearing a configured rate rejects the settings IPC call; the renderer does not handle that rejection.
- **Why it matters:** Users cannot disable the global speed limit through the advertised control.
- **Minimal fix:** Accept and persist the empty-string sentinel for this setting; retain validation for nonempty rate values. Handle update errors visibly. Do not normalize empty to an omitted patch that would preserve the old limit.
- **Regression test:** Set a nonempty limit, apply `{ downloadSpeedLimit: "" }`, and assert the persisted value is empty and subsequent download arguments contain no rate cap.

### A18 — Generated Media Tools thumbnails are outside the protocol's allowed roots

- **Severity:** Low. **Category:** renderer asset delivery. **Confidence:** High.
- **Files:** `src/main/download/media-probe.ts:20-28`; `src/main/index.ts:175-200`; `src/renderer/pages/media-tools-page.tsx:813-815`.
- **Problem/scenario:** Thumbnails are generated under userData/thumbnails, but the renderer requests them using `local:`. That protocol only allows the configured download root, so under normal settings generated thumbnails return 404.
- **Why it matters:** Native work is performed for a preview that cannot display. This is a functional mismatch, not a request to weaken path confinement.
- **Minimal fix:** Serve generated thumbnails through a narrowly authorized cache root or token-based handler; retain realpath containment checks. Do not grant access to all userData.
- **Regression test:** A generated thumbnail can be fetched; an adjacent userData file and a symlink/junction escape cannot.

## Probable issues

### P01 — Windows tree termination has a parent-first race and no taskkill failure handling

- **Severity:** Medium. **Category:** process-tree reliability. **Confidence:** Medium.
- **Files:** `src/main/download/process-registry.ts:83-100`; `test/process-registry.test.ts`.
- **Evidence/scenario:** The code launches `taskkill /T /F`, unrefs it, and immediately kills the root itself. If taskkill enumerates after the root disappears, descendant discovery may fail. Its error/exit result is not handled. The real parent/descendant smoke **passed**; an orphan was not reproduced, so this is not counted as confirmed.
- **Why it matters:** A passing immediate-child test does not prove yt-dlp/FFmpeg grandchildren always die, especially during shutdown.
- **Minimal fix if verified:** Let tree termination complete before a direct-child fallback, observe its error/exit, and bound shutdown waiting. Do not kill the discovery root first.
- **Regression test:** Windows-only parent/grandchild cases covering normal cancel, delayed taskkill startup, root exit, taskkill failure, and app shutdown; assert descendant termination, not just root exit.

### P02 — Media Tools can miss a terminal event before its waiter is installed

- **Severity:** Medium. **Category:** IPC/event ordering. **Confidence:** Medium.
- **Files:** `src/renderer/pages/media-tools-page.tsx:390-445,523-596`; `src/main/download/remux-job.ts:272-317`; `src/main/download/conversion.ts:262-274`.
- **Evidence/scenario:** `startOne` waits for start IPC, then stores the job ID and installs its completion promise. A terminal event arriving before that registration cannot resolve it, leaving the batch pending. Main starts work before returning the ID; actual Electron ordering for a sufficiently fast terminal path was not exercised.
- **Why it matters:** A failed or completed job may leave the batch UI stuck processing.
- **Minimal fix if verified:** After registering ownership, reconcile against current terminal history/state, or retain terminal results that arrive before the waiter. Avoid relying on event-vs-invoke timing.
- **Regression test:** A fake start bridge emits terminal state before resolving its job ID; the batch must still settle. Confirm with the real Electron surface before treating this as a reproduced UI failure.

## Improvements

### I01 — Put existing Windows failure tests and real Whisper work into release evidence

- **Severity:** Medium. **Category:** verification / release reliability. **Confidence:** High.
- **Files:** `.github/workflows/ci.yml:9-46,48-77`; `.github/workflows/release.yml:60-73,91-92`; `scripts/e2e/native-media.mjs:356-361`.
- **Benefit/scenario:** Regular unit tests run in Linux CI, while the Windows job runs native scripts but not `npm test`; the observed Windows stream-cleanup failure can therefore survive until a tag release. Release native tests skip actual Whisper transcription without `--whisper-model`, which the workflow does not supply.
- **Minimal change:** Run the existing cheap tests on Windows before release tags. Supply a small pinned/cached model to the packaged release smoke, or require an explicit recorded manual transcription gate. No new test framework or repeated full media suite is needed.
- **Preventive check:** Windows unit failure blocks merge; a release cannot silently report successful transcription verification when Whisper work was skipped.

### I02 — Narrow store subscriptions only if profiling shows a meaningful cost

- **Severity:** Low. **Category:** performance / unnecessary work. **Confidence:** High for broad subscriptions; Low for user-visible impact.
- **Files:** `src/renderer/app.tsx:14-34`; `src/renderer/components/row-card.tsx:100`; `src/renderer/stores/app-store.ts:131-160`; `src/main/download/job-state.ts:20-23`.
- **Benefit/scenario:** Components subscribe to the whole Zustand store even when they only need actions or a few fields. Progress changes therefore trigger avoidable renders. Main already coalesces updates to about 6–7 per second per job; no frame-time or interaction regression was measured.
- **Minimal change when justified:** Use existing Zustand selectors for stable actions/required fields. Do not add memoization layers, virtualization, a new state library, or cached transcript indexes without a measured bottleneck.
- **Preventive check:** Profile representative active jobs and a realistically sized library before/after; retain the change only for a measurable reduction in commit work or latency.

## Rejected concerns

- **“All Windows cancellation is broken.”** Rejected as a blanket claim. Registered jobs use `taskkill /T /F`, late registration respects cancellation, existing child tests passed, and a real descendant smoke passed. A04's missing ownership and P01's ordering risk remain distinct.
- **“Downloads have no crash recovery.”** `recoverPersistedJobs` calls startup reconciliation; nonterminal/legacy records become interrupted with `APP_RESTARTED`. Meaningful transitions are persisted immediately. This is interrupted-job recovery, not automatic continuation of all partial work.
- **“All temp cleanup is missing.”** Download work uses `os.tmpdir()/prism-downloads`, normal finally blocks clean it, and startup cleanup handles abandoned/legacy download roots. Paused work is intentionally preserved. This does not cover A10/A11's other roots or final files.
- **“Ordinary downloads always transcode.”** Format plans preserve/remux streams; explicit ProRes is the exceptional transcode path. Existing format/remux tests passed. No blanket codec-plan rewrite is warranted.
- **“A regular completed download can receive IPC cancellation halfway through its synchronous completion block.”** `ytdlp.ts:1460-1507` has cancellation checks and no await before completion writes. That particular interleaving is not possible on the main event loop. A14 has an actual asynchronous read boundary and is different.
- **“Renderer stale progress is entirely unprotected.”** Shared merge logic checks job/attempt/revision and late nonterminal events; snapshot merging preserves newer fields. These protections do not rescue records omitted by A01's stale whole-array write.
- **“The local protocol accepts simple path traversal or junction escapes.”** It checks lexical containment and resolved real paths. Preserve those checks. A18 concerns an omitted intended root, not a reason to remove validation.
- **“Transcript editing takes an arbitrary renderer path.”** Read/write transcript IPC takes a history ID; main derives the stored transcript path and bounds editable content size. That path is not directly interchangeable with `history:openFile`'s arbitrary path.
- **“Missing revokeObjectURL leaks previews.”** Renderer previews use `prism-media:` URLs, not browser-created blob URLs. Renderer rAF/subscription cleanup exists. The confirmed leak is main-owned cache/token lifetime.
- **“The native package layout is obviously wrong.”** Builder copies resources/bin to the path expected by packaged discovery; verification checks LFS pointers, sizes, hashes and PE architecture, and release runs packaged native scripts. No native layout rewrite was justified.
- **“The yt-dlp updater blindly installs remote bytes or races duplicate installs.”** It shares an in-flight install, checks exact-asset checksum/size, smoke-tests version, then changes its runtime pointer. No confirmed updater integrity/concurrency issue was retained.
- **“Only latest.yml means alpha updates must fail.”** Not established. GitHub channel generation differs from generic-provider channel rules, and GitHub updater code has a latest-channel fallback. Do not change release channels based solely on the prerelease suffix. References consulted: [electron-builder channel documentation](https://www.electron.build/docs/tutorials/release-using-channels/), [upstream GitHubProvider](https://github.com/electron-userland/electron-builder/blob/master/packages/electron-updater/src/providers/GitHubProvider.ts), [upstream metadata generation](https://github.com/electron-userland/electron-builder/blob/master/packages/app-builder-lib/src/publish/updateInfoBuilder.ts). Upstream inspection is not a packaged update smoke of the locked version.
- **“Unsigned alpha or newer dependencies require immediate migration.”** Unsigned Windows alpha status is documented; releases include checksums/signing status, native verification, and dependency-audit gates. No concrete dependency upgrade was established by this audit. Missing local tools are verification limitations, not evidence the repository's dependency declarations are broken.
- **“More abstraction will fix this repository.”** The valuable changes are ownership, terminal-state checks, stream teardown, destination reservation, and correct UI request construction. No new framework, queue rewrite, broad style pass, or speculative performance infrastructure is recommended.
